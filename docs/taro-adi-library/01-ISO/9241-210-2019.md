## Scope and why this matters to Taro

## Original operational rules

1. **ADI-ISO-9241_210_2019-H01** — Name users, their environments, abilities, constraints and actual tasks rather than inventing a generic persona.
2. **ADI-ISO-9241_210_2019-H02** — Record success criteria before drafting visual solutions.
3. **ADI-ISO-9241_210_2019-H03** — Make user needs distinguishable from stakeholder requests and implementation constraints.
4. **ADI-ISO-9241_210_2019-H04** — Explore at least one materially different workflow structure for ambiguous problems.
5. **ADI-ISO-9241_210_2019-H05** — Use observed task evidence, interviews or explicit assumptions rather than asserting unsupported user demand.
6. **ADI-ISO-9241_210_2019-H06** — Evaluate early designs against representative scenarios and accessibility needs.
7. **ADI-ISO-9241_210_2019-H07** — Track decisions and results so later iterations can learn from failure.
8. **ADI-ISO-9241_210_2019-H08** — Document known evidence gaps and avoid declaring compliance or usability without evaluation.

## What would fail the companion review

- User requirements are merely a list of screens
- Only a visually polished mockup is considered proof
- Testing never revisits initial assumptions
- Aesthetic preferences override observed user failures
